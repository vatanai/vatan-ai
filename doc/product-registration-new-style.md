# فایل اجرا: ثبت و ساخت محصول «سبک جدید» (Productic) — عکس

> تاریخ: ۹ مهر ۱۴۰۵ — اولویت اول چرخش به کسب‌وکار. قبل از هر کاری `doc/business-pivot-plan.md` را بخوان؛ این فایل جزئیات اجرایی همان بخش «ثبت محصول عکس» (تسک‌های 3.x و 5.x) است.
> قانون طلایی: **سیستم فعلی (چهره‌محور) نباید هیچ تغییر رفتاری کند.** بدون تأیید صریح محسن: deploy، push، migrate روی production ممنوع.

## ۰. خلاصه در ۶ خط

1. محصول جدید = «پک شات» برای یک محصول فیزیکی (سرم، کیف، کفش…). کاربر ۱ عکس محصول می‌دهد و چند شات تبلیغاتی سینمایی می‌گیرد.
2. در گام اول ثبت محصول (ادمین) دو گزینه: **چهره‌محور** (دقیقاً مثل الان) و **پروداکتی** (مسیر جدید).
3. شات‌ها با «زبان شات» (Shot Grammar) ساخته می‌شوند: توکن‌های دوربین/نور/دکور/انرژی؛ نه پرامپت جدا برای هر شات.
4. صفحه‌ی «بساز» برای محصول پروداکتی: بسته‌ی آماده (پیش‌فرض انتخاب‌شده) + تیک اختیاری شات‌ها + قیمت زنده.
5. قبل از ساخت، یک مدل بینای ارزان کیفیت عکس ورودی را بررسی/اصلاح می‌کند.
6. فاز اول فقط نیش آرایشی/عطر/زیبایی، فقط ادمین‌فقط (feature flag)، بعد برای عموم.

## ۱. تصمیم‌های نهایی (از پاسخ‌های مالک)

| موضوع | تصمیم |
|---|---|
| انتخاب شات توسط کاربر | بسته‌ی آماده + تیک اختیاری (کاربر عادی فقط دکمه می‌زند؛ حرفه‌ای‌ها شات‌ها را تیک/برمی‌دارند) |
| تعریف شات‌ها | کتابخانه‌ی مشترک شات (Shot Library)؛ ادمین در ثبت محصول تیک می‌زند کدام شات‌ها فعال باشند؛ پرامپت هر شات از قالب + توکن ساخته می‌شود |
| ایده‌ی کلمات میانبر | بله، شدنی: «زبان شات» (بخش ۴) |
| کیفیت | اولویت: ۱) شکل و رنگ محصول دقیقاً حفظ شود ۲) زیبایی و حس تبلیغاتی ۳) سرعت و قیمت پایین. لوگو/متن روی بسته: تلاش می‌کنیم ولی ضمانت نمی‌دهیم (در UI صادق باشیم) |
| ورودی | ۱ عکس اجباری + تا ۲ زاویه‌ی اختیاری + فیلتر کیفیت قبل از ساخت |
| قیمت | هر شات = تعداد مشخص کردیت؛ جمع زنده؛ در آینده پک‌های تخفیفی. نمونه‌ی هدف مالک: ۱۲۵ کردیت ⇒ ۵ عکس + ۳ ویدیو (یک «پست کامل») |
| نیش پایلوت | آرایشی/عطر/زیبایی (مثل طرح‌های مرجع HYPHEN و VÉLORA) |
| نمایش | کارت «پک» با کولاژ ۴ شات نمونه؛ محصولات چهره‌محور در تب جدا و دست‌نخورده |
| ایمنی اجرا | فیلد جدا `product_mode` + feature flag + پایلوت ادمین‌فقط. هیچ ستون فعلی تغییر معنا نمی‌دهد |
| سبک UI | هیگسفیلد/مدرن: تیره، سینمایی، تصویر بزرگ؛ طبق `doc/design-system.md` (توکن‌ها، YekanBakh، partial مشترک، «بزودی»، bump VERSION) |

## ۲. طرح‌های مرجع (چه دیدیم)

پوشه‌ی مرجع (Downloads/Telegram Desktop/New Folder With Items) دو سری دارد:
- **HYPHEN serum** (صورتی/ملایم): ۱) کلوزآپ مدل + انگشت روی پمپ + حلقه‌ی بادی صورتی ۲) محصول معلق/کج روی روبان‌های شیشه‌ای شفاف ۳) پروفایل مدل، محصول روی کف دست ۴) پرتره‌ی مدل با محصول کنار صورت + توت‌فرنگی روی سر.
- **VÉLORA serum** (نارنجی/طلایی): ۱) پاشش مایع طلایی + پرتقال + گل (hero انرژی) ۲) پایه‌ی سنگ تراورتن + نور آفتاب و سایه‌ی برگ + پرتقال و قطره (hero آرام).

درس‌ها: هر محصول ≈ ۴–۶ «کانسپت» ثابت دارد؛ همگی با **یک** هویت محصول (رنگ/شکل/لوگو) و حس برند یکسان. برای ما: کانسپت‌ها = شات‌های پک.

## ۳. معماری پیشنهادی (باید با کد واقعی تطبیق داده شود)

> فایل‌های مرتبط (قبلاً مرور شده): `Admin/ProductController.php`، `admin/products/create.blade.php`، `ProductBuildSchema`، `ProductPromptBuilder`، `ProductGenerateController`، `StudioWorkflowController`، `ProductCatalogController`، `app/create-product.blade.php`، `product.blade.php`، `routes/web.php` (ادمین ~خط ۵۱۲–۵۷۴). قبل از کدنویسی دوباره بخوان؛ اینجا فرض‌هاست نه حقیقت.

**جداول/فیلدهای جدید (همه additive و nullable/دیفالت امن):**
- `products.product_mode` (string، دیفالت `portrait`؛ مقدار جدید `product`). همه‌ی ۳۴۹ محصول فعلی می‌مانند `portrait`.
- `shot_library` : `id, key, name_fa, category(hero/lifestyle/model/detail/flatlay…), niche_tags(json), tokens(json), prompt_template, default_credits, aspect_ratio_default, sample_image, is_active, sort`.
- `product_shots` (pivot): `product_id, shot_id, enabled, credits_override, is_default, sort`.
- (فاز بعد) `shot_packs`: بسته‌های آماده (نام، لیست شات‌ها، تخفیف).
- `generations`/ساخت: ذخیره‌ی `selected_shots(json)` و `shot_id` هر خروجی؛ هر شات یک job مستقل ولی گروه‌شده در یک «سفارش» (batch) تا شکست یک شات کل را خراب نکند و فقط همان شات refund شود.
- Feature flag: `config('features.product_mode')` + whitelist ادمین‌ها؛ وقتی خاموش است، گزینه‌ی دوم در UI اصلاً دیده نشود.

**ثبت محصول (ادمین):**
- گام ۱ دو کارت بزرگ: «چهره‌محور» (همین مسیر فعلی، بدون تغییر) / «پروداکتی (جدید)». انتخاب کارت دوم → فرم جدید و ساده‌تر (نه ۵ گام فعلی با فیلدهای چهره).
- فرم پروداکتی: نام/نیش/دسته‌ی محصول → انتخاب شات‌ها از کتابخانه (تیک + ترتیب + قیمت هر شات) → سبک برند/پالت کلی (اختیاری) → مدل‌ها و کیفیت → پیش‌نمایش با عکس تست → ذخیره.
- شات نمونه‌ها: ادمین با یک عکس تست محصول، پیش‌نمایش هر شات را می‌گیرد و به‌عنوان تصویر کارت ذخیره می‌کند.

**صفحه‌ی ساخت (کاربر):** (route/ویوی جدید، نه تغییر `create-product.blade.php` فعلی؛ در صورت نیاز با شاخه‌ی شرطی روی `product_mode`)
1. آپلود عکس محصول (۱ اجباری، تا ۲ زاویه اختیاری) + راهنمای کوتاه عکس خوب (نور، پس‌زمینه ساده، کل محصول در کادر).
2. فیلتر کیفیت (بخش ۶): نتیجه‌ی سبز/زرد/قرمز و پیشنهاد اصلاح خودکار.
3. «بسته‌ی شات»: ۴ کارت تصویری بزرگ از پیش تیک‌خورده؛ کاربر می‌تواند هرکدام را بردارد یا شات‌های دیگر (+) اضافه کند. نوار پایین ثابت: «۴ عکس • ۴۰ کردیت • بساز».
4. (اختیاری) نسبت تصویر: ۴:۵ پست / ۹:۱۶ استوری / ۱:۱.
5. ساخت: نمایش شات‌ها به‌صورت کاشی‌هایی که یکی‌یکی پر می‌شوند (progressive) تا انتظار حس نشود؛ شکست یک شات = دکمه‌ی «دوباره + بازگشت کردیت همان شات».
6. نتیجه: گالری، دانلود تکی/همه، «ساخت ویدیو از این شات» (فاز ویدیو).

ساده‌سازی برای جلوگیری از گیجی: پیش‌فرض همیشه آماده؛ تیک‌زدن لایه‌ی دوم است («شات‌ها را شخصی‌سازی کن»).

## ۴. زبان شات (Shot Grammar)

هر شات = ترکیب توکن‌ها در این محورها:

| محور | نمونه‌ی توکن |
|---|---|
| framing | `hero-centered`, `closeup-macro`, `flatlay-topdown`, `three-quarter` |
| camera | `low-angle`, `eye-level`, `45deg`, `dutch-tilt`; لنز: `macro-100mm`, `85mm-portrait`, `35mm-wide` |
| lighting | `soft-window`, `hard-sun-leaf-shadow`, `softbox-studio`, `rim-light`, `golden-hour` |
| surface/set | `travertine-plinth`, `glass-ribbons`, `satin-fabric`, `wet-marble`, `pastel-seamless` |
| props/energy | `liquid-splash`, `levitation`, `ingredients-scatter`, `water-droplets`, `petals` |
| human | `none`, `hand-hold`, `model-closeup`, `model-profile`, `model-portrait-with-prop` |
| mood | `clean-luxury`, `playful-pop`, `warm-natural`, `editorial` |

- «پرامپت هر شات» = قالب ثابت + توکن‌ها + بلوک ثابت **حفظ محصول** (بخش ۵) + اطلاعات محصول (نام/رنگ/دسته).
- ادمین می‌تواند توکن‌های یک شات را ویرایش یا شات جدید با ترکیب توکن بسازد؛ برای هر نیش، یک «پک پیش‌فرض» از شات‌ها.
- مثال از مرجع: شات VÉLORA-hero = `hero-centered + low-angle + hard-sun-leaf-shadow + liquid-splash + ingredients-scatter + warm-natural`.

## ۵. وفاداری به محصول (Product Fidelity)

الان فقط `identity_preservation` (فقط چهره) داریم. باید حالت جدید `product_fidelity` اضافه شود (مستقل، بدون دست‌زدن به قبلی):
- بلوک ثابت در پرامپت: «محصول داخل عکس مرجع را عیناً حفظ کن: شکل، نسبت‌ها، رنگ، متریال؛ لوگو و متن را تغییر نده/اختراع نکن؛ فقط صحنه، نور و محیط عوض شود».
- ارسال عکس(ها)ی محصول به‌عنوان مرجع به مدل ویرایش تصویر؛ ترجیحاً مدل‌هایی که چند تصویر مرجع می‌گیرند.
- شاخص کنترل کیفیت: بعد از ساخت یک بررسی ارزان (VLM) «آیا محصول با ورودی یکی است؟» و در صورت رد، یک بار خودکار دوباره بساز (سقف ۱ بار؛ هزینه‌ی دوباره‌سازی را محاسبه کن).
- محدودیت صادقانه: متن ریز روی بسته ممکن است خراب شود؛ در UI بنویس «برای بهترین نتیجه عکس واضح از جلوی محصول بده».

## ۶. فیلتر کیفیت ورودی (Pre-flight)

- یک مدل بینای ارزان (کلاس Gemini Flash / GPT-mini؛ انتخاب قطعی با آزمون) خروجی JSON بدهد: `usable`, `issues[]` (blur, dark, cropped, busy_bg, multiple_products, has_person, low_res), `crop_box`, `suggestion_fa`.
- اگر قابل‌اصلاح: بریدن/صاف‌کردن پس‌زمینه/بهبود نور با یک مرحله‌ی ارزان (حذف پس‌زمینه یا ادیت سبک) و نمایش «قبل/بعد».
- اگر غیرقابل‌استفاده: پیام فارسی روشن و درخواست عکس جدید؛ هزینه‌ای از کردیت کسر نشود.
- از سایت‌های مشابه (Higgsfield, Photoroom, Pebblely, Flair, Claid، Adobe Firefly product…) الگو بگیر: بررسی کن چطور ورودی را می‌گیرند، چند خروجی می‌دهند، قیمت‌گذاری و UI چیست (تسک پژوهش 3.R در پایین).

## ۷. قیمت و هزینه

- فرض فعلی: کردیت ≈ ۵۸۵ تومان در پلن کسب‌وکار؛ GPT Image 1.5 edit ≈ ۰٫۰۳۴$ ≈ ۷٬۸۸۳ تومان به ازای یک ساخت ۱۲ کردیتی (مرجع قبلی). مدل‌های ارزان‌تر غیرچهره‌محور باید اندازه‌گیری شوند.
- **تسک آزمون هزینه (قبل از قیمت نهایی):** روی ۱۰ عکس محصول واقعی آرایشی، ۲–۳ مدل (OpenRouter/Fal) را با همان ۴ شات اجرا کن؛ جدول «هزینه‌ی هر شات / درصد حفظ محصول / زیبایی» بساز. مدل پیش‌فرض = ارزان‌ترین که در حفظ محصول مردود نمی‌شود.
- قیمت هر شات = هزینه‌ی واقعی × ۳ تا ۴ (حاشیه) به کردیت گرد شود؛ شات ویدیو جدا.
- پک آینده: «پست کامل» = ۵ عکس + ۳ ویدیو ≈ ۱۲۵ کردیت (قابل تنظیم پس از آزمون).
- کنترل ضرر: سقف روزانه‌ی هزینه‌ی API در ادمین؛ هشدار وقتی هزینه‌ی واقعی > ۵۰٪ درآمد.

## ۸. تسک‌ها (برای تیک‌زدن؛ شناسه‌ها با چک‌لیست ۸۷‌تایی هم‌خوان)

**فاز A — آماده‌سازی (بدون تغییر رفتار)**
- 3.R پژوهش سایت‌های مشابه (Higgsfield، Photoroom، Pebblely و…): ورودی، تعداد خروجی، UI انتخاب سبک، قیمت. خروجی: ۱ صفحه خلاصه.
- 3.A بازخوانی کد واقعی ثبت و ساخت؛ جدول «نقاط تماس» که باید شرطی روی `product_mode` شوند.
- 3.B آزمون هزینه/کیفیت مدل‌ها (بخش ۷) روی ۱۰ عکس.
- 3.C ساخت ۶–۸ شات آرایشی با Shot Grammar و تست روی ۵ محصول (VÉLORA/HYPHEN و محصولات واقعی).

**فاز B — پایه‌ی داده و کنترل**
- 3.D migration additive: `product_mode`، `shot_library`، `product_shots`، فیلدهای batch. Rollback‌پذیر؛ تست روی دیتابیس لوکال کپی.
- 3.E feature flag + whitelist ادمین؛ تست: با flag خاموش هیچ تغییری در UI/خروجی (snapshot تست).
- 3.F سرویس `ShotPromptBuilder` (توکن → پرامپت) + بلوک `product_fidelity`؛ تست واحد.

**فاز C — ثبت محصول (ادمین)**
- 3.G گام ۱ با دو کارت؛ مسیر چهره‌محور = کد فعلی بدون تغییر.
- 3.H فرم پروداکتی + انتخاب شات + پیش‌نمایش با عکس تست.
- 3.I مدیریت Shot Library (CRUD ساده).

**فاز D — صفحه‌ی ساخت (کاربر)**
- 3.J UI آپلود + فیلتر کیفیت (بخش ۶) + نوار قیمت زنده.
- 3.K بسته‌ی آماده + تیک اختیاری؛ ساخت batch با کاشی‌های progressive؛ refund تکی هنگام خطا.
- 3.L نمایش در اکسپلور/کاتالوگ: کارت «پک» با کولاژ ۴ شات؛ تب جدا برای کسب‌وکار.
- 3.M طراحی هیگسفیلد‌گونه با توکن‌های دیزاین‌سیستم + حالت روشن/تیره + موبایل ۳۶۰px.

**فاز E — اعتبارسنجی و عرضه**
- 3.N تست انتها‌به‌انتها با ۵ محصول واقعی آرایشی؛ ثبت نرخ موفقیت و هزینه‌ی واقعی.
- 3.O تست رگرسیون: ساخت یک محصول چهره‌محور قدیمی دقیقاً مثل قبل کار کند (اسکرین‌شات قبل/بعد).
- 3.P bump VERSION، به‌روزرسانی CHANGELOG/doc؛ **انتظار تأیید مالک** برای deploy.
- 3.Q بازکردن flag برای ۵ کاربر منتخب، سپس عموم.

## ۹. معیارهای پذیرش

1. محصولات قدیمی بدون هیچ تغییری ثبت و ساخته می‌شوند (تست رگرسیون سبز).
2. با flag خاموش، هیچ اثری از حالت جدید دیده نمی‌شود.
3. یک محصول آرایشی جدید در کمتر از ۵ دقیقه ثبت می‌شود و ۴ شات فعال دارد.
4. کاربر با ۱ عکس و ۲ کلیک ۴ شات می‌گیرد؛ شکل/رنگ محصول در ≥۸۰٪ شات‌ها درست است.
5. شکست یک شات فقط همان شات را refund می‌کند.
6. هزینه‌ی واقعی هر پک < ۴۰٪ قیمت فروش.

## ۱۰. ریسک‌ها

- متن/لوگوی روی بسته خراب شود → در UI شفاف بگو + QC خودکار + قابلیت ساخت دوباره.
- هزینه‌ی چندبرابر (چند شات در یک ساخت) → سقف هزینه و آزمون قبل از قیمت.
- پیچیدگی UI → پیش‌فرض بسته‌ی آماده، تیک لایه‌ی دوم.
- آسیب به سیستم فعلی → فیلد جدا، flag، تست رگرسیون، migration additive.
- صف و RAM سرور برای batch → شات‌ها را پشت‌سرهم/با concurrency کم اجرا کن و آزمون بار بگیر.

## ۱۱. سؤال‌های باز (در چت جدید با مالک تأیید شود)

- نام فارسی بخش جدید در منو (مثلاً «استودیو محصول»؟).
- حداکثر شات در یک ساخت (پیشنهاد: ۶).
- آیا برای هر نیش سبک برند (پالت/حس) از کاربر پرسیده شود (اختیاری)؟
- ویدیو از شات: فاز بعد، با همین Shot Grammar (حرکات `dolly-in`, `crane-up`, `rack-focus`…).

## ۱۲. پرامپت شروع برای چت جدید

> `doc/business-pivot-plan.md` و `doc/product-registration-new-style.md` را کامل بخوان. هدف: پیاده‌سازی «ثبت و ساخت محصول پروداکتی (سبک جدید) برای عکس» طبق تسک‌های 3.A تا 3.Q، بدون آسیب به مسیر چهره‌محور. از فاز A شروع کن (پژوهش، بازخوانی کد، آزمون هزینه)، یافته‌ها را به مالک بگو و منتظر تأیید بمان. بدون تأیید صریح deploy/push/migrate روی production نکن. پس از هر فاز خلاصه بده.
