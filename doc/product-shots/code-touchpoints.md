# 3.A — بازخوانی کد و نقاط تماس «محصول پروداکتی» (پک شات)

> تاریخ: ۱۰ مهر ۱۴۰۵. از روی کد واقعی شاخه‌ی `crm-integration` (کامیت `6f928bc`).
> قانون: مسیر چهره‌محور هیچ تغییر رفتاری نکند؛ همه‌ی تغییرها additive و پشت فلگ.

## آنچه در کد پیدا شد

| فایل | یافته | پیامد برای طرح |
|---|---|---|
| `ProductGenerateController::generate` (~۸۰۰ خط) | «مدل‌های خروجی چندگانه» (`output_variants`): برای هر واریانت یک اجرا با پرامپت جدا، هزینه × تعداد، کسر فقط برای خروجی‌های موفق | الگوی درست است، ولی **همه‌ی اجراها پشت‌سرهم در یک درخواست HTTP** انجام می‌شود ← برای ۴ تا ۶ شات روی سرور ۱ گیگی خطر timeout و کشته‌شدن worker (گزارش ۲۷ شهریور) |
| همان متد | رزرو اتمیک (`CreditWalletService::reserve/settle/restore`)، ثبت `Order`، گالری، پاداش سازنده، پیامک | همین سرویس‌ها در موتور شات **دوباره‌استفاده** می‌شوند؛ خود متد دست نمی‌خورد |
| `AiProviderRouter::generateForProduct` | مسیریابی provider + fallback + ثبت `ai_provider_requests` | موتور شات همین را صدا می‌زند ← گزارش مالی و هزینه خودکار درست می‌ماند |
| `ProductPromptBuilder` | فقط بلوک «حفظ هویت چهره» | سرویس جدا `ShotPromptBuilder` با بلوک `product_fidelity`؛ PromptBuilder فعلی دست نمی‌خورد |
| `OpenRouterService::scoreLabImage` / `generateStructuredText` | تماس مدل بینای ارزان با خروجی JSON | فیلتر کیفیت ورودی و QC خروجی روی همین زیرساخت (متد عمومی جدید و additive) |
| `Admin\ProductController::store` (~۳۰۰ خط) | فرم ۵ گامی، ستون‌های NOT NULL: `name_fa`, `name_en`, `slug`, `category`, `thumbnail`, `primary_model`, `prompt_template` | فرم پروداکتی کنترلر **جدا** دارد و همین ستون‌ها را با پیش‌فرض امن پر می‌کند |
| `Product::booted` | `created_by` / `updated_by` خودکار از گارد admin | محصول پروداکتی هم ثبت‌کننده دارد (بخشی از 3.5) |
| `ProductGenerateController::create` | صفحه‌ی «بساز» برای همه‌ی محصولات عکس | **تنها نقطه‌ی شاخه‌ی شرطی در مسیر کاربر**: اگر `product_mode = product` و فلگ برای کاربر باز است ← ویوی جدید پک |
| ۲۰+ نقطه‌ی فهرست محصول (اکسپلور، ترندز، هوم‌بیلدر، کاتالوگ، سایت‌مپ، بات…) | همه `Product::query()->where('status','active')` | محصول پروداکتی تا وقتی فلگ عمومی نشده در فهرست‌های عمومی دیده نشود ← اسکوپ محلی در نقاط فهرست اصلی |
| تست‌ها | PHPUnit با sqlite؛ همه‌ی ۲۸۹ مایگریشن روی sqlite اجرا می‌شوند | تست‌های جدید با `RefreshDatabase` و مایگریشن واقعی |
| خط پایه‌ی تست | ۳۰۳ تست، **۵۶ شکست قبلی** (پیش از هر تغییر؛ اغلب وابسته به محیط) | معیار رگرسیون: هیچ شکست جدیدی اضافه نشود |

## نقاط تماس (چه چیزی شرطی می‌شود)

| # | نقطه | تغییر | رفتار با فلگ خاموش |
|---|---|---|---|
| 1 | جدول `products` | ستون `product_mode` (پیش‌فرض `portrait`) + `shot_settings` (json، nullable) | همه‌ی محصولات فعلی `portrait`؛ هیچ کدی آن را نمی‌خواند مگر مسیر جدید |
| 2 | ثبت محصول ادمین | دکمه/کارت انتخاب نوع در لیست و فرم ← کنترلر و ویوی جدا | کارت «پروداکتی» دیده نمی‌شود؛ فرم ۵ گامی عیناً همان |
| 3 | صفحه‌ی «بساز» (`ProductGenerateController::create`) | یک `if` در ابتدای متد | شرط false ← همان کد قبلی |
| 4 | فهرست‌های عمومی | اسکوپ `hideUnavailableProductModes()` | فقط محصولات پروداکتی پنهان؛ نتیجه‌ی بقیه دقیقاً یکسان |
| 5 | موتور ساخت | سرویس جدید `ShotGenerationService` + جداول `shot_batches`, `shot_batch_items` | استفاده نمی‌شود |
| 6 | روت‌ها | روت‌های جدید با پیشوند `product-shots` | middleware فلگ ← 404 |

## تصمیم‌های معماری

1. **هر شات = یک درخواست HTTP جدا** با `batch` مشترک (به‌جای حلقه‌ی هم‌زمان داخل یک درخواست). مرورگر با هم‌زمانی ۱ تا ۲ اجرا می‌کند. نتیجه: کاشی پیش‌رونده‌ی واقعی، refund مستقل، درخواست کوتاه.
2. **قیمت ثابت هر شات** (`credits_override` یا `default_credits`)، رزرو و تسویه/بازگشت برای همان شات.
3. **فلگ دولایه:** کلید اصلی `PRODUCT_SHOTS_ENABLED` در env (قطع اضطراری) + تنظیمات در دیتابیس (`product_shot_settings`): روشن/خاموش، مخاطب (فقط ادمین / لیست سفید / عموم)، لیست سفید کاربر. پیش‌فرض: خاموش.
4. **سقف هزینه‌ی روزانه‌ی API** و هشدار «هزینه > ۵۰٪ درآمد» از روی آیتم‌های همین موتور.
